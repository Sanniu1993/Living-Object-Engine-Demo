## 2026-07-05

- 发现 DeepSeek 做判官问题很多：会把"一致"当问题报、会自创"逻辑矛盾"去点评剧情、
  Memory 变大后还会重复退化把 JSON 撑爆导致崩溃。
- 猜测：便宜模型 Instruction Following 不足，做判官不靠谱。
- 已做：Prompt 硬约束 + 代码兜底（类别过滤、max_tokens、重试、逐章落盘）把噪音和崩溃压下去。
- 发现：Memory 效果方向上像是有用（减少术语/人名漂移），但两次 A/B 方向相反，判官噪音 + 小样本让结论不稳。
- 下一步：换 GPT/Claude 判官验证（接口已留好），同配置多跑几轮看方差。
- 另注意到一个真实译文缺陷：DeepSeek 翻日本人名时姓/名顺序不稳定（Hiruzen Sarutobi ↔ Sarutobi Hiruzen）——
  候选下个实验：给 Translator 加 Style Guide 看能否降低 name drift。
- 用户拿 ChatGPT 复核译文，最大发现：DeepSeek 几乎不加/删/改剧情（保真度好），最大短板是"小说味"。
  → 把问题分成 A 类（术语选得不够好）和 B 类（LLM 腔）。A 类不是一致性问题、是 canonical 译名本身差。
- 做了 EXP-003（种子术语表）：预置 62 条权威译名后，A 类从源头修好，5 章 QA 全部一次通过、零修订。
  收获：修 glossary 初始质量 >> 事后 QA 兜底。B 类（小说味）种子解决不了，留给 EXP-004。
- 用 Opus 逐句复核第1章：保真度高（无加/删/改剧情），残留是几处成语直译 + 火影/Naruto 误译 + 翻译腔。
- 做了 EXP-004（Translator 加译法规范规则）：3 个必修错误修好 2.5 个（背黑锅、原身修好；火影/Naruto 半修）。
  贯穿性发现：prompt 规则能治"死记硬背"型错，治不了"需要语境推理"型错——和 QA 判官那条结论一样。
  → 语境类残留 + 小说味都指向同一个天花板：便宜模型。要再上一层得换强模型。
- 接了 AIHubMix（GPT-5 mini 当 QA 判官）。踩坑：它是推理模型，max_tokens=2048 被推理吃光→返回空，加到 8192 才好。
- 做了 EXP-005（受控对比判官）：GPT-5 mini 命中 3/3、DeepSeek 0/3；GPT-5 mini 还抓到 DeepSeek 全漏的人物关系语义错。
  大发现：我们为压 DeepSeek 噪音把 prompt 收得太紧，结果把它的检测力也一起阉割了——现在 DeepSeek 判官面对明显错误都返回 0。
  GPT-5 mini 唯一毛病是"用名/称谓"过度严格（误报），一条 prompt 规则可修 → EXP-006。
- 做了 EXP-006（压判官误报）：加"用名/称谓不算不一致"白名单。第一版太宽，把植入的 "Orochi" 当简称放过了（3/3→2/3）——
  自己又踩了一次"收紧 prompt 削掉检测力"的坑。收窄成"截断单名要报"后，恢复 3/3 且误报清零。
  关键心得：白名单要划精确边界（用名的一部分 vs 截断单名），不能笼统"简称都放过"。
- 还注意到：判官有 run-to-run 随机性，最强的语义 catch（新之助关系错）时报时不报——单次结果有噪音，要多跑取平均才严谨。
- 做了长篇加固（EXP-007 前置）：extract/translate 改用有界紧凑视图（O(N²)→O(N)）、resume 断点续跑+幂等、默认关复查省判官。
- 跑了 EXP-007（真实 30 章切片）：加固都成立（成本平、一致性零漂移）。暴露两问题：
  ① 源文件脏（第68章起编号重启+重复，盗版聚合导出常见）——不是框架 bug，跑前得验源文件。
  ② 判官漏译盲区：20% 章残留未翻中文（判官只查一致性抓不到）。加确定性"漏译闸"（正则扫CJK+补译）修好。
  心得复用：能确定性判的别用 LLM——判官管语义、正则管漏译。这跟 EXP-006"边界要精确"是一路的。
