# EXP-008 — 别名合并的陷阱：canon 假设 vs 源文事实

**日期：** 2026-07-06

## 背景
翻译到 41-50 章时发现源文里 `大和` 和 `天藏` 疑似指同一角色（canon 里 Yamato = Tenzō 是同一人）。
为消除"读者看到两个名"的困惑，提议把两者合并成一个英文名，并据一次快速确认执行了合并：
`大和 / 天藏 → Tenzo`，改了 glossary 并把已翻 4 章的 "Yamato" 替换成 "Tenzo"。

## 出了什么错
**它们其实是两个不同的人。** 去查源文上下文才发现：
- `大和` = 漩涡水户命名/收养的**木遁孩子**（ch33 "就叫他大和如何"），即 canon 的 Yamato。
- `日向天藏` = **日向一族族长、日向日差的亲生父亲**（ch10 明写），是本书的**原创角色**，与 Yamato 无关。

合并把两个角色搅成一个名，污染了 glossary + 4 章译文。

## 根因
- **凭 canon 假设 + 一句快速确认就动了 Memory，没有先核验源文上下文。**
  如果一开始就 grep 一下 `天藏`，会立刻看到 `日向天藏`（族长），根本不会去合并。
- 提问方式也有诱导：把 `大和/天藏` 预设成"canon 同一人 Yamato/Tenzō"，让确认方也被带偏。

## 修复
- 拆开：`大和 → Yamato`（木遁孩子）、`日向天藏 → Tenzo Hyuga`（日向族长）、`天藏 → Tenzo`。
- 回滚 ch33/34/35/41 的 "Tenzo" → "Yamato"（这 4 章只有木遁孩子，无族长，回滚安全）。
- 族长所在的 ch10/45-50 本就正确译为 "Tenzo Hyuga"，未受影响。

## 产出：确定性防呆检查
新增 `check_name_collisions.py`：扫 glossary 里"多个源文名 → 同一英文名"的情况，逐条让人确认是
"真别名(同一实体)"还是"误合并(不同实体)"。跑当前 Memory：6 处撞名，全是合法别名
（如 土流壁/土遁·土流壁、天藏/天蔵）——若误合并还在，会冒出 `Tenzo ← 天藏 / 天蔵 / 大和`，
`大和` 一眼出戏，当场可抓。

## 结论 / 教训
- **写 Memory（尤其"合并实体"）必须以源文证据为准，不能靠 canon 假设或一句确认。**
  "人工知识注入"这一层本身也会引入系统性污染——它同样需要一道确定性护栏。
- 至此校验分三层，各管一类、缺一不可：
  1. **确定性正则**（漏译闸）——管"有没有中文没翻干净"
  2. **LLM 判官**——管"语义/术语一致性"
  3. **人工别名 + 撞名检查**（本篇）——管"实体身份的合并/拆分"，且人工判断要有确定性检查兜底
- 元教训：连"看似合理的人类判断 + AI 附和"都能把 Memory 带坏。可靠系统要让每个写入点都可被独立复核。
