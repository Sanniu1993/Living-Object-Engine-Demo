# EXP-009 — 单语流畅度审校（小语种质量盲区）

**日期：** 2026-07-06

## 目的
加了阿拉伯语目标语言后，验证现有质量链条（一致性 QA + 确定性漏译闸）在小语种上够不够；若不够，找出漏在哪、补一层什么。

## 假设
一致性 QA 和确定性漏译闸都是围绕"源语言=中文、目标语言底子好（英语）"设计的。预测在阿拉伯语上会出现一类**既不违反术语一致性、也不是残留中文**、但母语者一眼看出不对的质量问题（语法残句、逐字硬翻），现有两层都抓不到。

## 修改
相对 v1.7：
- **多语言化**（v1.8）：抽取器「只理解不翻译」→ 理解语言无关、跨语言复用；glossary 按语言分区 `{lang: {...}}`；新增 `languages.py` 语言插口（en/ar/es）。
- **L0 删作者话**（v1.9）：`splitter.strip_author_notes` 确定性删"求月票/追读/拜托"等段落。
- **L1 教训回灌**：把人工发现的 4 类阿语译法坑写进 `languages.py` 的 ar `translator_notes`。
- **L2 单语流畅度审校**（v1.9）：新增 `workflow_review.py`，判官**只看译文、不看原文/Memory**，抓语法错误/生硬直译/前后矛盾三类，产出 issue 复用现有 reviser 修复。`--fluency` 开关，默认关。

## 实验设置
- 对照：同一条流水线，开/不开 `--fluency`
- Benchmark：Chapter 1~2（阿拉伯语；偏离 1~5 基准，因本次只为验证盲区是否存在，非规模测试）
- 翻译/修复：DeepSeek　｜　一致性判官 + 流畅度判官：GPT-5 mini

## 结果

两章的一致性 QA **全部"通过"**，但流畅度审校仍抓到问题，且全部修复：

| | 一致性 QA | 流畅度问题 | 修复率 | 残留中文 |
|---|---|---|---|---|
| 第1章 | 通过 | 9（多为语法残句 + calque） | 9/9 | 无 |
| 第2章 | 通过 | 4（全为生硬直译/外来 token） | 4/4 | 无 |

### 关键发现：抓到确定性漏译闸抓不到的"外来 token 残留"
第2章两条 high：
- `ميزته情报ية` —— 中文词"情报"被塞进阿拉伯词**内部**（脏 token）。
- `أنSubjects` —— 译文里直接落下**英文单词** "Subjects"（模型漏译）。

第二条是 `find_untranslated_cjk`（只扫中文 CJK）**结构上抓不到**的：目标语混进的是英文，不是源语言。第一条虽是中文、CJK 正则理论上能扫到，但它嵌在阿语词中间，属于生成"卡壳"产物。

### L2 与人工判断对齐
第1章我人工找到的语法残句（"心里一动"译成半句 `تحريك في قلبه`）被 L2 独立抓到（#5），且 L2 还多抓了 4 处我漏看的残句——判官在"单语通顺度"上比我细。

## 结论
- 假设成立：**一致性和流畅度是正交维度**。一致性 QA 全绿 ≠ 译文能读；小语种上尤其明显（便宜模型阿语生成更毛糙）。
- **确定性漏译闸有个结构性盲区：只认源语言（中文）残留，认不出混进来的英文/其他语言 token。** L2 单语审校恰好补上这块——而且它不靠"对照原文"，纯以母语语感判断，成本只多一次判官调用（输入还比一致性 QA 小，因为不喂 Memory）。
- 复用了老教训：判官易空返（推理模型吃光配额）→ 沿用 EXP-002 的 8192 token + 重试；判官易噪音 → 沿用三类白名单 + 条数上限 + "不确定不报"。
- 保留：样本仅 2 章，"修复率 13/13"只能说"这一层确实在干活"，不能推断全本覆盖率与误伤率。reviser 改写幅度是否会伤到没被点名的句子，未系统核验。

## 下一步
- 跑 1~5 全量 `--fluency`，出 L2 的问题密度 + 是否引入回归（改写溢出）的数据。
- **L3 双语忠实度**（对照原文抓语义偏差，如"丝滑小连招"被误解为武打）——建议先看 L2 覆盖率再决定要不要，因为它输入翻倍、最贵。
- **L4 换翻译模型 A/B**：小语种用强模型翻译 vs 便宜翻译+多轮修复，用现成 `--ab-test` 比总账。
- 把 L1 的静态 `translator_notes` 升级成进 Memory、逐章成长的 `style_rules`——让"译法教训"也变成 Living Object（最贴合核心论点，改动最大）。
