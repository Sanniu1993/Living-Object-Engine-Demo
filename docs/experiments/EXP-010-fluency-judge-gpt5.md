# EXP-010 — 流畅度判官换 GPT-5（vs GPT-5 mini）

**日期：** 2026-07-06

## 目的
流畅度审校（L2，EXP-009）目前用 GPT-5 mini 当判官。小语种（阿语）单语审校最吃语感，验证换更强的 GPT-5 是否值得。

## 假设
更强的判官在"语法/生硬直译/前后矛盾"上应召回更多真问题、且 run-to-run 更稳。代价是更慢更贵。

## 修改
- `llm_client.get_client` 加 `fallback_role`：新增 "fluency" 角色，默认回退到 "qa"（不配就和一致性QA同模型）。
- `main.py` 用 `get_client("fluency", fallback_role="qa")` 单独给流畅度审校配判官。
- `.env` 配 `FLUENCY_LLM_MODEL=gpt-5`（对应 CHANGELOG v1.10）。

## 实验设置
- 输入：**同一份** 第3章阿语"原始译文"（只翻译、不做任何修复），两个判官看完全一样的文本才公平。
- 判官：GPT-5 mini vs GPT-5（都走 aihubmix）。各跑 **2 轮**看噪音。
- Benchmark：Chapter 3（偏离 1~5 基准，本次为单章判官对比）。

## 结果

### 先撞到一个基础设施坑（重要）
GPT-5 在 `max_tokens=8192` 下**两轮全空返**——推理模型的 max_tokens 是"推理+输出"总额，8192 被内部推理吃光、没剩给输出。逐档加大：**16000 起**才吐得出 JSON。
→ 修复：`REVIEW_MAX_TOKENS` 8192 → 24000（mini 用不满、无额外成本；gpt-5 才够）。**这是 EXP-002/007 "判官空返" 教训的升级版：模型越强，输出预算要留得越大。**

### 给足预算后的对比（同一份 ch3 原始译文）
| | GPT-5 mini | GPT-5 |
|---|---|---|
| 8192 预算 | 7~8 条/轮 ✅ | 空返 ❌ |
| 每轮条数 | 7, 8 | 15, 15 |
| 去重后总数 | 15 | **22** |
| 两者重叠 | — | **仅 3 条** |
| 类型分布 | 直译11/语法3/矛盾1 | 直译20/语法7/矛盾3 |

- **更全**：22 vs 15，且两judge只重叠 3 条 → 各有盲区，gpt-5 覆盖明显更广。
- **更稳**：15+15（几乎不抖）vs 7+8（有波动）。
- **更深**：gpt-5 抓到一处 mini 完全漏掉的**指代错误**——"لقد أعدّت زوجتك"（你妻子做的菜），但做饭的是老师的妻子琵琶湖、不是大蛇丸的；这是要理解上下文才看得出的语义错，不是表面语法。
- 人工抽查 gpt-5 独有的 19 条：基本都是真问题（阿语性数一致、calque 且给了更地道的替换），**不是凑数噪音**。

## 结论
- 假设成立且强于预期：GPT-5 在阿语单语审校上更全（+~50%）、更稳、能抓语义级错误。**小语种的 L2 判官值得上 GPT-5。**
- 但有前提：**必须给足输出预算（≥16000）**，否则静默空返、比 mini 还差——这条不修，"换更强模型"会变成"换了个更差的"。
- 成本换质量：gpt-5 更慢更贵，适合定稿质量档；快速迭代仍可用 mini。已做成可配置（`FLUENCY_LLM_*`），两档随时切。

## 下一步

- 一致性 QA 仍是 gpt-5-mini；若也想上 gpt-5，需同样把 QA_MAX_TOKENS 提上去（别重复踩空返坑）。
- L3 双语忠实度审校仍待做（能把修复回流进 idioms 库）。
