# EXP-002 — QA 判官（DeepSeek）的噪音与崩溃

**日期：** 2026-07-05

## 目的
搞清楚为什么 QA 结果不可信、以及第 4 章为什么崩溃，并把 QA 这个"测量工具"修可靠。

## 背景 / 现象
用 DeepSeek 同时做翻译和 QA 判官时，QA 输出出现四类问题：
1. **中英混淆**：把"译文是英文、Memory key 是中文"误判为不一致，报出"应该用中文"的假问题。
2. **确认性噪音**：大量"XX 一致，无问题 / 不报告"被塞进 `issues` 数组当成问题计数。
3. **自创类别**：跑去点评剧情合理性、角色动机，自造"逻辑矛盾"类别（不在允许的三类里）。
4. **重复退化 → 崩溃**：第 4 章 Memory 膨胀后，判官陷入重复循环（"一致，不报告"出现 105 次），
   输出超长被截断，JSON 解析失败，整轮实验崩溃。

## 修改（逐条对症）
| 现象 | 措施 |
|---|---|
| 中英混淆 | Prompt 讲清 key 是中文原文、要比的是英文译法（v0.3） |
| 确认性噪音 | Prompt 禁止"一致/不报告"条目；代码只按空/非空判 passed（v0.3, v0.5） |
| 自创类别 | Prompt 硬约束"只查三类、禁止评价剧情"；代码 `ALLOWED_TYPES` 过滤（v0.6） |
| 重复退化崩溃 | Memory 按章裁剪、`max_tokens` 收紧、最多 20 条、失败重试、逐章落盘（v0.5） |

## 结果
- 第 4 章不再崩溃，**QA 成功率 100%**（5/5 章）。
- 总 issue 数从 78/50 降到 21/23；越界的"逻辑矛盾"点评条目消失。
- 但**残留噪音未根除**：DeepSeek 仍会漏出"使用 X（一致），但出现 Y（不一致）"这类半噪音条目。

## 结论
**DeepSeek 适合做翻译，但做 QA 判官不可靠**（指令遵循弱：越界、复述、重复退化）。
Prompt + 代码兜底能压住大部分噪音，但压不干净 —— 想要可信指标，判官需要更强的模型。
